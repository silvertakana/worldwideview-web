# Billing launch evidence

Reproduction evidence for the billing launch hardening. These documents were written while
rehearsing the billing launch against the local billing test stack, and until now they lived
only in scratch directories outside version control. This directory is the first in-repo copy,
committed so the claims can be reviewed next to the code they are about.

## What is here

| Path | What it is |
|---|---|
| `group-a/FINDINGS.md` | Verdicts and mechanisms for the six Group A (money safety) break-it scenarios. |
| `group-a/LIMITS.md` | What the Group A evidence does not prove, and the known weaknesses of its harness. |
| `group-a/groupa-reproduce.ps1` | Driver that regenerates the Group A run. |
| `group-a/groupa-harness.mjs` | The 53-check Group A harness that the driver executes. |
| `defense/FINDINGS.md` | Two confirmed defects: hub silent payment loss (D1) and globe instant lockout (D2). |
| `defense/LIMITS.md` | What the D1 and D2 evidence does not prove. |
| `defense/d1-reproduce.ps1`, `defense/d2-reproduce.ps1` | Drivers that regenerate the D1 and D2 runs. |
| `defense/d1-harness.test.ts`, `defense/d2-harness.test.ts` | The harnesses those drivers copy into a scratch worktree and run. |

## What is deliberately not here

The raw run transcripts and logs were left out on purpose. They are bulky, they quote the same
source and the same output that the FINDINGS documents already summarise, and every one of them
can be regenerated by running the drivers above.

| Omitted | Produced by |
|---|---|
| `GROUPA-TRANSCRIPT.txt` | `group-a/groupa-reproduce.ps1` |
| `D1-TRANSCRIPT.txt`, `D2-TRANSCRIPT.txt` | `defense/d1-reproduce.ps1`, `defense/d2-reproduce.ps1` |
| `_hub-dev.log`, `_groupa-harness.stdout.txt`, `_d1-stdout.log`, `_d2-stdout.log`, `_orchestrator.log` | the drivers, and the dev servers they start |
| `_baseline/` source snapshots | captured copies of the pre-fix sources |

Two consequences of that decision are worth stating plainly, because otherwise the documents
read as if something is missing:

- `group-a/FINDINGS.md` names `GROUPA-TRANSCRIPT.txt` as its companion artifact, and
  `defense/FINDINGS.md` cites `D1-TRANSCRIPT.txt` and `D2-TRANSCRIPT.txt`. Those citations are
  accurate. The transcripts exist on the author's machine; they are simply not tracked here.
- `group-a/FINDINGS.md` also refers to a `baseline/` directory of pre-fix source snapshots for
  its falsification run. That directory is not tracked either.

## Path convention

Absolute paths were rewritten to relative ones before committing, because the originals embedded
a local machine layout. Paths are now relative to the local ecosystem root, meaning the directory
that holds the main checkouts and their sibling worktrees, with scratch and decision documents
under `temp/`. So `worldwideview-web.fix-billing-launch-hardening` means the worktree
`<ecosystem-root>/worldwideview-web.fix-billing-launch-hardening`, and
`temp/billing-launch-readiness.md` means `<ecosystem-root>/temp/billing-launch-readiness.md`.

Nothing else in these documents was changed. The drivers take every path as a parameter with a
default, so override the defaults (`-EvidenceWorktree`, `-HubWorktree`, `-GlobeWorktree`,
`-OutDir`, and so on) to point at real locations on your machine before running them.

Two referenced documents live outside this repository and are not included:
`temp/billing-launch-readiness.md` (the launch-readiness decision document that defines the
Group A scenarios) and `temp/billing-launch-branch-status.md`.

## Credentials in these files

`group-a/groupa-harness.mjs` and `defense/d1-reproduce.ps1` contain Supabase `iss=supabase-demo`
JWTs. The harnesses also contain placeholder Stripe webhook signing secrets, a placeholder
cross-service secret, and synthetic `@example.com` and `@repro.local` addresses. These are the
public local-dev values that the Supabase CLI ships and that Supabase's own documentation uses,
not production credentials. They match the values already present in `docker-compose.test.yml`,
and `.gitleaks.toml` allowlists these exact tokens by their `supabase-demo` payload.

## Running the drivers

```powershell
pwsh -File docs/billing-evidence/group-a/groupa-reproduce.ps1 -OutDir <dir>
pwsh -File docs/billing-evidence/defense/d1-reproduce.ps1 -OutDir <dir>
pwsh -File docs/billing-evidence/defense/d2-reproduce.ps1 -OutDir <dir>
```

Each driver writes a transcript into its `-OutDir`. The results recorded in the FINDINGS
documents belong to the specific commits those documents name. A run against a different commit
is a new result to be judged on its own, not a confirmation of the recorded one.
